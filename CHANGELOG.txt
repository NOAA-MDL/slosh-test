2024-01-29  Synchronized with P-Surge v3.0.4 (2023-07-26)
  * Add CPT=0 and INTEGER*2 RESTART.  When SLOSH is run a second time in a
    different basin than the first, there is a chance for erroneous wave flux
    energy to creep in from the edge of the basin.  The result is slightly
    different (order of round-off), but is detectable due to randomness of
    P-Surge first-come-first scheduler.  Additionally, the RESTART variable is
    set in the C code to 'short' (aka INTEGER*2) and is passed to FORTRAN.
    Unfortunately FORTRAN didn't declare it INTEGER*2 (defaulted to INTEGER*4).

2024-01-29  Synchronized with P-Surge v3.0.3 (2023-07-11)
  * Set DMIN to 50ft (vs 0).  Wave energy is transferred between the wave model
    and the surge model if cell depth is < DMIN.  DMIN should be 50 feet, but
    was set in the "initial common" routine to 0, and not reset (by a DATA
    statement).  Thus no wave energy was transferred to the surge model.

2012-06-08  !! Changing NHRAD creates an extra time-step
   * Recalculating MHALT (stop computations) based on changes to NHRAD
   * SETCMP() was doing a time-step advance.  Since STMVAL() also did a
     time-step advance, there was a double step for delp,rmax,x,y during
     the first time-step.
        The delp,rmax are reset every hour based on the value from file, so they
     recovered after the first hour; however the position information doesn't
     reset, so it continues to be off by "about" a time-step.  The "about" is
     because the FWD speed info is used to move the storm and it is reset on the
     hour, so the storm would follow a slightly different track.
        The result is that Rmax/Delp after the first hour is correct, but the
     position is off by about a DT.  Not much, but enough to impact the results.
   * Adjusting how NHRAD is initialized so the switch in time-steps occurs on
     the hour rather than 1 time-step before the hour.  This will make the
     model run 1 time-step longer before switching (both times) and 1 time-step
     longer overall.
